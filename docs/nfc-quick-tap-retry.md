# 快速贴卡的重试与错误区分

## 本次修复

原实现把本地读卡、AES 认证和服务端校验放在一个 `runCatching` 内，任何失败都返回 `Rejected`，导致快速移卡也显示“卡片错误”并关闭扫描。

修复后沿用官方扫描窗口，读取失败时更新提示并等待用户移开、再次贴卡，不取消当前流程，不使用上次卡片结果，也不跳过认证。

- **通信中断、读取不完整、失效 Tag、校验信息未完整取得**：提示“请再试一次。先移开卡片，再贴紧手机，直到扫描完成。”保留扫描窗口；每次重贴都重新读取和验证。
- **完整芯片信息确认不支持，或 AES 认证阶段明确返回密钥不匹配**：提示“卡片错误”，不进入下一步。文件读取阶段的认证状态丢失不当作错误卡。
- **本地身份读取和服务端校验均通过**：返回本次认证的身份，按原流程进入下一步；绑定钱包等后续限制不变。
- **网络超时、服务端暂时故障、限流**：单独提示检查网络后再贴卡，不能当作错误卡或离线放行。
- **服务端明确未批准校验**：提示卡片校验未通过，并停止推进，不混同于卡片型号错误。
- **NFC 关闭或不可用**：提示开启 NFC，不显示“卡片错误”。

Android 将离开感应区导致的读卡失败报告为 `TagLostException`（属于 `IOException`），并不证明卡片型号或归属有误。[Android 官方说明](https://developer.android.com/reference/android/nfc/TagLostException)

## 并发与安全

同一时刻只执行一次物理读取。每次读取绑定到启动它的扫描请求；取消后的迟到结果、重复回调和新扫描之前的结果均不允许更新已接受身份或推进流程。重试次数不会自动转化成“不是我们的卡”。

后台 NDEF 只是打开应用的元数据，不是可信的物理读卡结果；未知后台记录也不会取消前台扫描。继续保留上一版“指定打开自有钱包”的功能。

## 实卡验收（待执行）

1. 打开扫描提示后快速贴一下并移开：应显示重试提示，扫描窗口保留。
2. 再快速贴两次：不能显示卡片错误，不能进入下一步。
3. 将同一张有效测试卡贴稳：认证后进入原定下一步。
4. 用不支持的卡或不同密钥的测试卡贴稳：确认后显示卡片错误，不推进。
5. 断网扫描自有卡，再恢复网络重贴：先显示网络提示，恢复校验后继续。
6. 读取过程中取消，再发起新扫描：上一轮结果不得关闭或完成新窗口。
7. 确认中文 / 英文随系统语言显示，沿用官方扫描窗口。
