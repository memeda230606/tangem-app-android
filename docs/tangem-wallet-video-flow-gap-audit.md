# Tangem 钱包视频流程对照与测试清单

更新时间：2026-09-03\
适用版本：`googleExternal` / L0 TESTNET

## 结论

视频中的收款、兑换、发送、手续费选择、结果页、访问码和生物识别界面在原钱包中已经存在。原实现真正缺失的是：外部 NTAG 卡扫描后创建的是带静态公钥的模拟冷钱包，不能完成真实签名；恢复分片组件也没有接入创建和恢复入口。

本次已把外部卡模式改成“真实手机热钱包 + 卡片在场授权”：私钥由 Tangem Hot SDK 生成并留在 Android Keystore，NTAG 卡只用于绑定、备份分片和签名前的实体卡验证，卡片本身不持有钱包私钥，也不执行区块链签名。

## 流程对照

| 视频流程 | 原状态 | 本次修复后的行为 | 真机验收重点 |
| --- | --- | --- | --- |
| 扫描主卡并创建钱包 | 扫描后保存静态公钥模拟钱包 | 未绑定卡进入真实手机钱包创建；生成真实密钥后绑定当前卡 | 换卡、伪卡或已绑定其他钱包的卡必须失败 |
| 立即备份 | 三方恢复组件未接入 UI | 创建恢复包；随机包装密钥使用 Shamir 2-of-3 分为客户码、卡片、服务器三份 | 完成前钱包不得显示“已备份”；保存好 `NBRC1-` 恢复码 |
| 设置访问码与生物识别 | 已有 | 保留原流程；三方恢复包成功后继续进入访问码和生物识别 | 重启应用后访问码/生物识别仍能解锁 |
| 查看收款地址/二维码 | UI 已有，但模拟钱包地址不可用于真实签名 | 地址来自真实热钱包公钥，并强制映射到测试网 | 从交易所测试网小额转入并核对到账地址 |
| 钱包内 Swap | UI 和报价流程已有 | 交易最终签名前必须重新扫描绑定卡；验证失败不释放签名 | 测试网报价可用时进行小额兑换；取消刷卡不得广播 |
| 输入地址、金额和手续费并发送 | UI 已有，但模拟钱包不能真实签名 | 保留原页面；单签和多签都在 Hot SDK 签名前要求重新扫描同一绑定卡 | 错卡、取消、服务器验证失败时不得签名或广播 |
| 发送成功与到账确认 | 已有 | 保留原结果页和交易状态刷新 | 用测试网浏览器和交易所记录双重核对交易哈希 |
| 钱包恢复 | 无可用入口 | 导入页接受 `NBRC1-` 恢复码；读取客户码 + 卡片分片（并校验服务器保存的恢复包），导入后核对承诺公钥指纹 | 新设备恢复后地址必须与原钱包完全一致；错误码/错误卡必须失败 |

## 安全边界

- 仅 `external` 构建启用这套逻辑；普通版本行为不变。
- 外部卡钱包标记为 `isTestnetOnly`，钱包管理器只创建对应测试网实例；无法映射到测试网的链直接不可用。
- 签名前检查交易哈希非空、重新扫描实体卡，并核对卡片绑定的钱包标识。
- 卡片不保存助记词、私钥、PIN 或交易签名秘密；恢复包密文由随机包装密钥加密，卡片仅保存其中一份分片。
- 恢复后必须再次计算真实钱包公钥指纹，与备份时承诺的指纹恒等匹配；不一致立即删除新导入的本地钱包。
- NFC 授权失败时 Hot SDK 的签名函数不会被调用。

## 真机联合测试顺序

1. 准备一张未绑定 L0 TESTNET 卡和一张属于其他钱包的卡。
2. 用未绑定卡创建钱包，完成三方恢复包、访问码和生物识别设置。
3. 记录钱包测试网地址和 `NBRC1-` 客户恢复码；恢复码离线保存，不上传工单或聊天。
4. 从交易所测试网转入最小金额，核对地址、网络、余额和交易哈希。
5. 发起最小金额转出：分别验证取消扫描、刷错卡、正确卡三种结果。
6. 若测试网 Swap 服务能返回报价，执行一次最小金额兑换并检查签名前刷卡。
7. 在清除本机测试钱包数据后，用 `NBRC1-` 恢复码和原卡恢复；核对恢复地址与步骤 3 完全一致。
8. 用错误恢复码、错误卡和篡改后的恢复数据各测试一次，均应失败且不得产生新钱包或签名。

## 环境前置条件

以下属于联合测试环境，不是客户端流程缺口：

- 后台 `/verifications`、`/claims`、`/recovery-packages` 服务可用，且服务器恢复分片的 KEK/KMS 配置正确。
- 手机具备 NFC，并能读取卡片安全动态消息及受保护恢复文件。
- 目标链测试网 RPC、测试币水龙头、广播服务可用。
- Swap 是否能实测取决于供应商是否为目标测试网返回有效报价；无测试网报价时只能验证到签名拦截之前。

主网交易仍被刻意禁用。完成以上 TESTNET 联调、安全评审和恢复演练前，不应解除该限制。
