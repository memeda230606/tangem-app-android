# Tangem 官方 UI 扫卡点真机测试清单

更新时间：2026-09-03\
适用版本：`googleExternal` / L0 TESTNET\
测试原则：UI 和交互顺序遵循官方流程；钱包密钥由手机安全区保存，L0 卡只负责实体在场授权、恢复分片和签名前验证。

## 每次扫卡的固定动作

所有测试都使用同一套贴卡顺序，避免卡片在扫描窗口出现前被系统提前读取：

1. 先把卡片移开手机至少 5 厘米。
2. 在钱包内点击会触发扫卡的按钮。
3. 等待官方“轻触以扫描”页面完整出现。
4. 再把卡片贴到手机背面上方、摄像头附近的 NFC 区域。
5. 保持不动，直到出现成功、失败或下一流程页面。
6. 页面离开扫描界面后再移开卡片。

验收通则：没有出现“轻触以扫描”前直接贴卡，不得启动微信公交卡、系统公交卡服务或其他应用，也不得绕过钱包按钮直接授权。

## B. 登录与识别流程

### B01 已绑定卡，本机已有钱包

- [x] 完全关闭钱包应用后重新打开；访问代码保护正常，输入后进入原钱包。
- [x] 从“详情 → 添加钱包”触发扫描，看到“轻触以扫描”后贴 `TC-1FCB94195D72`。
- [x] 实测：扫描会话完成后回到原 `Wallet`（移动钱包），未创建第二个钱包，也未出现导入页或公交卡服务。

### B02 已绑定卡，本机没有对应钱包

- [ ] 在另一台未保存该钱包的测试手机上安装同版本钱包。
- [ ] 从欢迎页扫描 `TC-1FCB94195D72`。
- [ ] 预期：进入官方“创建移动钱包”选择页，显示“导入现有钱包 / 创建钱包”。
- [ ] 点击“创建钱包”。
- [ ] 预期：提示“钱包已存在”，不得覆盖服务器绑定或生成新钱包。

### B03 其他钱包的已绑定卡

- [x] 在当前钱包所在手机上扫描一张绑定到其他钱包的 L0 测试卡（首次实测）。
- [x] 首次实测失败：扫描后错误地返回当前钱包。原因是旧式扫描入口复用了统一的 External 模拟卡公钥，只验证卡片有效性，没有先比较服务器钱包绑定。
- [x] 第一次修复复测仍失败：服务器已识别为异钱包绑定，但“详情 → 添加钱包”使用的回调式扫描入口进入了“创建移动钱包”页面。
- [ ] 两种扫描入口均已增加异钱包绑定拦截，并改用不显示卡片编号的通用提示；新包已安装，待复测。预期：显示不匹配提示，不得打开当前钱包、进入创建/导入、重新绑定或进入签名。

### B04 未初始化、伪造或非 L0 卡

- [ ] 扫描普通空白 NFC 卡、未完成 L0 初始化的卡或内容被修改的卡。
- [ ] 预期：认证失败，不创建钱包，不产生绑定，不启动公交卡服务。

### B05 冻结或已作废卡

- [ ] 分别扫描后台状态为 `FROZEN` 和 `REVOKED` 的测试卡。
- [ ] 预期：服务器拒绝验证；钱包不能解锁、恢复或签名。
- [ ] 注意：冻结/作废会改变后台状态，执行前必须单独确认测试卡范围；不要对当前有效主卡直接操作。

## C. 创建与三方备份

### C01 新卡创建钱包

- [ ] 使用另一张未绑定 L0 测试卡重复新钱包创建。
- [ ] 预期流程：扫描卡片 → 创建钱包 → 创建成功 → 备份钱包。
- [ ] 记录创建后的测试网收款地址，用于后续恢复地址比对。

### C02 创建恢复包

- [ ] 在“备份钱包”页点击“立即备份”。
- [ ] 等“轻触以扫描”出现后扫描刚才绑定的同一张卡。
- [ ] 预期：卡片分片写入成功、服务器分片入库，并显示唯一的 `NBRC1-` 客户恢复码。
- [ ] 在确认保存恢复码前，钱包不得标记为“已备份”。
- [ ] 后台应出现 `TESTNET_RECOVERY_PACKAGE_CREATED`，恢复包状态为 `ACTIVE`。

### C03 备份时使用错误卡

- [ ] 在 C02 的扫描步骤改用其他钱包的卡。
- [ ] 预期：提示卡片不属于该钱包；不得创建恢复包，不得显示“备份完成”。

### C04 取消或中断备份扫描

- [ ] 在“轻触以扫描”页取消，或扫描过程中移开卡片。
- [ ] 预期：返回备份页并显示失败/取消；钱包保持未备份状态，可重新尝试。

## D. 钱包恢复

优先使用第二台测试手机。若只能在当前手机清除应用数据，会删除本机钱包和设置，必须在记录原测试网地址及确认恢复码有效后另行批准。

### D01 正确恢复码 + 正确卡

- [ ] 在没有本地钱包的设备上扫描已绑定卡。
- [ ] 点击“导入现有钱包”，输入离线保存的 `NBRC1-` 恢复码。
- [ ] 点击“恢复”，等待“轻触以扫描”后再次扫描同一张绑定卡。
- [ ] 预期：客户分片和卡片分片完成 2-of-3 恢复，服务器返回加密恢复包。
- [ ] 预期：恢复后的测试网地址与 C01 记录的地址逐字符完全一致。
- [ ] 预期：后台产生 `TESTNET_RECOVERY_PACKAGE_ACCESSED` 成功事件。

### D02 错误恢复码 + 正确卡

- [ ] 输入另一钱包的恢复码或修改恢复码任意字符，再扫描正确卡。
- [ ] 预期：恢复失败；不得生成可用钱包，不得显示原钱包地址。

### D03 正确恢复码 + 错误卡

- [ ] 输入正确恢复码，但扫描绑定到其他钱包的卡。
- [ ] 预期：卡片绑定校验失败；不得恢复、不得改绑。

### D04 恢复时取消扫卡

- [ ] 输入正确恢复码后，在扫描页取消。
- [ ] 预期：停留在恢复流程，可安全重试；不得留下半成品钱包。

### D05 服务不可用

- [ ] 在隔离测试条件下断开网络或停用测试接口，再执行恢复。
- [ ] 预期：恢复失败并保持关闭状态；客户端不得只靠卡片和客户码绕过服务器校验。

## E. 交易签名前扫卡

当前 L0 钱包的所有真实 Hot SDK 签名都会先执行绑定卡授权。以下项目都只使用测试网最小金额。

### E01 普通转账

- [ ] 收款页面复制测试网地址，并转入最小测试币。
- [ ] 发起最小金额转出，完成地址、金额和手续费确认。
- [ ] 预期：最终签名前出现“轻触以扫描”，扫描正确绑定卡后才生成签名并广播。
- [ ] 记录交易哈希，并在对应测试网浏览器确认到账。

### E02 转账取消扫卡

- [ ] 到最终签名扫描页后取消。
- [ ] 预期：不签名、不广播，余额不因该笔测试变化，后台没有成功授权结果。

### E03 转账扫描错误卡

- [ ] 最终签名时扫描其他钱包的卡。
- [ ] 预期：显示卡片不匹配；不调用 Hot SDK 签名，不广播交易。

### E04 Swap

- [ ] 在测试网供应商能返回报价时发起最小金额兑换。
- [ ] 预期：确认兑换后的最终签名前再次要求扫描绑定卡。
- [ ] 分别验证取消、错误卡、正确卡；只有正确卡允许继续。
- [ ] 若测试网无报价，记录为“环境不支持”，不能记为客户端失败。

### E05 WalletConnect 交易签名

- [ ] 连接测试网 DApp，发起一笔测试网交易签名。
- [ ] 预期：钱包确认页之后要求扫描绑定卡；正确卡才可签名。
- [ ] 分别验证取消和错误卡均不会向 DApp 返回成功签名。

### E06 WalletConnect 消息签名

- [ ] 由测试 DApp 发起消息签名。
- [ ] 预期：显示待签内容，并在真实签名前要求扫描绑定卡。
- [ ] 取消或错误卡不得产生签名结果。

### E07 其他链上动作

- [ ] 质押、取消质押、领取奖励或合约授权等操作如进入真实签名阶段，同样必须出现扫卡。
- [ ] 只需选择当前测试网实际支持的一项验证；主网必须保持禁用。

## F. NFC 时序与异常稳定性

### F01 扫描窗口出现前贴卡

- [ ] 钱包停留在普通页面时先贴卡。
- [ ] 预期：不得直接授权，不得跳转公交卡服务、微信或其他应用。
- [ ] 移开卡片后，通过钱包按钮重新进入“轻触以扫描”再贴卡，应可正常读取。

### F02 快速重复贴卡

- [ ] 一次成功后立刻移开并再次贴回。
- [ ] 预期：同一授权只消费一次，不重复创建钱包、恢复包或交易签名。

### F03 扫描中途移开再贴回

- [ ] 认证过程中移开卡片，再按页面指引重试。
- [ ] 预期：第一次操作明确失败或取消；第二次重新认证，不复用残留会话。

### F04 锁屏、切后台和重启

- [ ] 扫描页切到后台再返回。
- [ ] 锁屏后解锁再尝试扫描。
- [ ] 重启手机后重新打开钱包并扫描绑定卡。
- [ ] 预期：没有卡死、重复授权或错误跳转；每次都必须重新显示扫描窗口。

## G. 官方存在、但当前 L0 卡不适用的扫卡流程

以下页面属于官方 Tangem 硬件卡功能，需要能执行 Tangem APDU 的原厂芯片。当前 NTAG 424 DNA L0 卡只做手机钱包授权，不能把这些项目当成 L0 缺陷：

| 官方扫卡流程 | 当前 L0 状态 | 说明 |
| --- | --- | --- |
| 在卡片安全芯片内部创建钱包私钥 | 不适用 | 当前私钥由 Tangem Hot SDK 生成并留在 Android Keystore |
| 备份到第二、第三张 Tangem 卡/指环 | 已替换 | 当前采用客户码 + L0 卡片分片 + 服务器分片的 2-of-3 方案 |
| 查看原厂卡详细信息 | 不支持 | 依赖 Tangem Card SDK 和原厂 APDU |
| 修改卡片访问码 | 不支持 | 当前设置的是手机应用访问码，不是原厂卡访问码 |
| 卡片访问码恢复 | 不支持 | 依赖多张原厂备份卡及原厂恢复命令 |
| 恢复出厂设置/清除卡内钱包 | 禁止测试 | 当前 L0 卡不保存区块链私钥；该操作还具有破坏性 |
| 手机钱包升级为原厂硬件钱包 | 不支持 | 需要支持密钥导入的 Wallet 2.0 原厂卡 |
| Tangem Pay / Visa 卡激活与证明 | 不支持 | 需要专用支付卡、服务端资格和原厂卡证明 |
